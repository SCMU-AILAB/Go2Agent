# Normality：通用视觉任务实施方案

## 目标与当前基线

让操作者用自然语言描述目标，机器人结合最新视觉、深度、运行状态和执行反馈，从注册能力中选择动作，并持续判断目标是否达成。

首个贯通案例：**“看见人后跟着他走，保持 1.5 米距离；人停下时停止，人消失时停止。”** 后续在同一套机制下支持“看见挥手就回应”“有人靠近时打招呼”“先跟随，收到停止指令后停止”等任务。

泛化范围是已有感知与技能可以完成的任务。无法识别的对象、未实现的动作、缺少必要传感器的任务应返回明确的能力缺口，不能编造技能或把任务替换成挥手。

分支 `Normality` 从 `7e01ebeab673987af4d96c08107d6772a983d39a` 创建。当前工作区保留共享视觉模型排队与 429 恢复修复。此次只创建分支和方案，不改变狗上的运行版本。

当前限制：

- `src/app/backend.py` 为 UnifoLM 选择 `gesture_label`；`src/agent/social_vision.py` 使用固定手势提示词，并以关键词映射少数动作。
- 系统提示词与用户任务混合用于关键词匹配，可能导致跟随任务误触发挥手。
- 当前 Go2 目录没有 `follow_person`；人员感知缺少横向位置字段。
- 前端/API 仍以 `gesture` 表达视觉任务，不能准确呈现持续行为的运行、暂停和阻塞原因。
- `test` 分支已有通用 JSON 决策和跟随技能，可按功能迁移；不能整分支覆盖后假定问题已经解决。

## 架构

```text
用户指令 → 任务规格与能力检查 → 持续任务管理器
                                  ↑           ↓
RGB/深度 → 最新世界状态 → 模型决策 → 结构化校验 → SkillRuntime
                ↑                      ↓           ↓
           执行反馈与状态 ← 本地控制器 ← 持续行为 / 有界动作
```

### 1. 任务规格

保留用户原始指令，将系统规则与用户任务分开。模型生成结构化任务规格，包含目标、目标对象、可测参数、触发条件、完成/停止条件和不明确项。

例如跟随任务包含 `target=single_visible_person`、`target_distance_m=1.5`、`stop_on_target_loss=true`。如果用户只说“保持一定距离”，使用可配置默认距离并在前端显示；多个目标无法确定时等待选择或澄清。

优先支持一个当前任务，替换任务时先取消旧执行、停止运动，再启动新任务。复杂多步骤任务在基础闭环稳定后实现。

### 2. 感知与世界状态

分开维护语义证据与运动所需数值，所有数据带帧编号、单调时间和有效性：

- 本地人员检测：边界框、中心位置、深度、检测可信度。
- 目标跟踪：目标 ID、可见性、遮挡、歧义和目标丢失。
- 环境约束：可用深度、前方障碍距离、机器人连接与遥测状态。
- VLM：与当前任务相关的场景和行为证据，标记来源帧；不能把推测当作测量距离。

初版先限制一个可见人员。先评估现有人体检测在狗视角、背对相机和移动画面中的表现，再决定是否引入更稳的人体检测模型。多人身份保持与路线跟踪单独验收。

### 3. 模型决策

模型接收用户任务、最新有效感知、当前执行状态、上次结果和技能目录，只返回符合 schema 的 JSON。

沿用并收紧 `AgentDecision`：`execute_skill`、`continue`、`interrupt`、`ignore`、必要的语音响应；参数必须符合所选技能的 schema。技能目录显式标注有界动作、持续行为、前置条件和自主执行权限。

移除通用入口中的“必须看见手”“必须是手势”“看见人不能行动”等任务无关规则；这些条件只适用于相应手势任务。拒绝未知技能、越界参数和自主任务中不可调用的技能。

先比较两条推理路线，再确定默认配置：

1. UnifoLM 直接输出任务决策 JSON，减少一次模型调用。
2. UnifoLM 输出短语义证据，文本模型结合技能目录生成决策；用于直接 JSON 路线准确率不足的情况。

以任务正确率、首个有效决策延迟、陈旧决策比例和共享负载表现选择，不能仅凭模型输出看起来合理判断。

### 4. 执行与实时控制

复用 `SkillRuntime` 的参数校验、资源互斥、取消和结果反馈。持续技能只启动一次，模型返回 `continue` 不重复启动；执行结束或阻塞后由最新证据决定下一步。

`follow_person` 使用本地人员位置和深度持续控制，不等待每轮 VLM 才更新速度。距离、速度上限和目标选择通过类型化参数传入，执行前校验范围。

第一版定义为“朝一个可见人员跟随并保持距离”。严格“沿着人的路径走到其身后”需要额外轨迹、定位与局部路径规划，不能用目标居中控制宣称已实现。

目标丢失、多目标歧义、深度失效、数据过期、障碍接近、遥测不可用、取消或异常退出都需要走统一停止路径。SDK 调用成功表示命令被接受；是否达到目标需结合传感器和状态反馈。

### 5. 延迟与共享模型

相机采集独立运行，推理使用最新帧；每个任务至多一个在途推理，不积压历史画面。任务版本变化或决策超过该行为允许的证据时效时，丢弃结果。

保留有界服务端排队和客户端 429 恢复；推理服务拥堵不能让运动控制等待陈旧结果。运动安全由本地控制链路独立保证。

不恢复固定五秒冷却或通用手势确认时长。重复动作采用任务与事件状态处理：同一次挥手只回应一次，手放下后再次挥手形成新事件；持续跟随保持同一个执行实例。

## 实施阶段与验收

| 阶段 | 主要工作 | 验收标准 |
| --- | --- | --- |
| 1：通用任务入口 | 分离用户指令与系统规则；加入视觉任务规格；统一 JSON 决策和技能能力检查；兼容旧 `gesture` API | 跟随指令不会生成挥手；无能力任务说明缺口；未知技能、参数错误被拒绝；三种不同任务复用同一入口 |
| 2：人员感知与跟随 | 迁移 `test` 中人员位置、跟随技能和逐帧更新链路；加入距离参数及数据有效性；先用录制帧和模拟机器人验证 | 人在左/右对应正确转向；远处接近、目标距离处停止；目标丢失、障碍、取消和异常都调用停止；模型停响应时本地控制仍受感知约束 |
| 3：完整闭环与时效 | 贯通任务状态、执行结果、取消、事件去重、共享推理恢复；评估一段式/两段式模型路线 | 不重复启动持续技能；过期结果不会执行；旧任务结果不能作用于新任务；429 不终止观察；挥手结束后不执行旧挥手决策 |
| 4：前端与可观测性 | 将“手势任务”扩展为“视觉任务”；展示目标、参数、执行状态、感知有效性、等待/阻塞原因与停止入口；删除确认时长配置 | 用户能区分看不见目标、正在推理、技能被拒绝、SDK 失败与正常保持距离；API 和前端无确认时长字段依赖 |
| 5：真机验收与扩展 | 先只读感知，再低速单人跟随；验证停止与取消后扩展到多人跟踪和多步骤任务 | 完成下述场景矩阵；每个新增能力有明确前置条件、失败反馈和证据；记录版本、参数、性能和未支持场景 |

按依赖顺序提交可独立审阅的功能，避免把旧版本的全部行为一次性替换。迁移依据为 `test` 分支的实际差异，优先提取跟随、人员坐标、结构化决策和时效控制；逐项检查其手势专用限制与参数写死问题。

阶段 1–4 的实施、模拟验证及预留项见 [normality-validation.md](normality-validation.md)。阶段 5 不在本次执行范围内；全程不操作真实机器狗。

## 验证与性能指标

必要测试集中在行为契约：任务与技能匹配、参数边界、执行状态转换、数据过期、旧任务结果隔离、取消后停止，以及模型/SDK 失败恢复。使用录制画面、假模型和模拟机器人覆盖这些情况，避免测试发出真机运动。

真机场景：无人、一个人进入、背对狗行走、左右移动、停止、距离过近、目标离开、遮挡、第二人进入、前方障碍、摄像头断开、推理服务拥堵、操作者停止和新任务替换。

统一记录：采集到推理的帧年龄、排队时间、模型耗时、首个有效决策延迟、控制使用的数据年龄、SDK 耗时、目标距离误差和停止延迟。比较单机器人与两机器人共用模型的 p50/p95。

初始工程预算（待实测调整，并非当前能力承诺）：本地控制目标周期 20–50 ms；跟随感知有效期不超过 500 ms；失效触发本地停止请求的目标延迟不超过 100 ms。需要分别记录停止请求与物理停止，SDK 超时等问题可能影响后者。

## 第一批具体改动

1. `src/app/backend.py`、`src/app/api.py`：通用视觉入口、任务版本、取消和状态反馈；兼容旧客户端。
2. `src/agent/social_vision.py`、`src/agent/decision.py`：独立用户任务、通用 JSON 契约、动态能力描述与权限过滤；逐步将通用逻辑从手势类命名中拆出。
3. `src/agent/unifolm_vision.py`、`src/agent/vision_policy.py`：推理路线比较、最新帧策略、时效校验和可恢复错误。
4. `src/perception/`：人员坐标、深度匹配、时间戳和目标状态。
5. `src/skills/motions/go2_follow.py`（新增）、`src/skills/go2_catalog.py`：可配置跟随能力与资源声明。
6. 前端任务提交与状态组件：通用视觉任务、参数展示、阻塞原因和停止控制。

最先交付一个经过模拟验证的通用入口与单人跟随闭环，再部署真机验证。路线规划、多人身份保持和复杂任务组合不列入首批完成声明。
